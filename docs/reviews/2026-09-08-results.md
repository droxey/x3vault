## Remaining Limits And Recommendations

- No physical XTEINK device was available. Verify a representative vault,
  ownership initialization, dry-run, upload, deletion, and rendered links/images
  on the actual firmware before relying on the release. HTTP fixtures validate
  the client contract; they do not establish firmware compatibility.
- The local Go 1.26.8 smoke attempt failed while resolving VCS metadata in the
  linked worktree. Go 1.27.1 smoke and acceptance checks passed there; hosted CI
  runs smoke on both versions in a full checkout. No VCS checks were disabled.
- Execution checks ran on Linux. Windows and macOS behavior, permissions, and
  rename semantics were not exercised on those operating systems.
- Sync remains incremental. A failed transfer can leave a partial device update;
  fix the error and rerun it. Upload failures now prevent obsolete-file deletion.
- The enabled hash cache trusts same-size remote content when its receipt matches.
  Use `sync.hash_manifest: false` to detect external same-size edits or recover
  from a malformed cache, as documented in the README.
- Use a dedicated build root and run one build or sync at a time. Builds serialize
  themselves; the workflow does not promise transactional coordination with
  another process that replaces files during sync. Canonical checks and regular
  file restrictions do not constitute a general hostile-filesystem sandbox.
- A killed build can leave its lock directory. Remove it only after confirming
  no build is running. See the README for recovery instructions.
- Keep the pinned Go patch releases and analysis tools updated as security fixes
  ship. The standards and vulnerability results are a snapshot of this review.

All recorded findings have a completed disposition. This does not claim that
inspection and testing prove the absence of every possible defect.
